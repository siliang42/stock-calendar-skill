# A 股热点事件日历用户 Wiki 设计

## 目标

在仓库中新增一套可直接同步到 GitHub Wiki 的 `wiki/` 页面，帮助首次使用者完成打开日历、安装 Skill、更新数据、配置自动任务和排查常见问题。

## 读者与边界

- 主要读者是项目使用者，不假设其了解项目内部实现。
- 内容以任务和可执行命令为中心，只解释完成操作所需的架构与数据格式。
- Wiki 不承诺仓库尚未实现的能力。豆包的搜索、文件上传和文件展示属于平台能力；系统 cron 需要用户另行提供实际执行入口。
- Wiki 不重写现有源码或业务数据，也不扩展项目功能。

## 页面结构

| 页面 | 目的 |
|---|---|
| `Home.md` | 说明项目能力、适用场景、前置条件和推荐阅读路径 |
| `Quick-Start.md` | 用最短路径打开日历并生成首个 Excel |
| `Install-as-a-Skill.md` | 说明 Skill 目录结构、导入、触发与验证 |
| `Update-Calendar-Data.md` | 说明三类日历数据的编辑方式和重新构建流程 |
| `Automation-and-Deployment.md` | 区分豆包平台任务与普通系统 cron，给出部署和验证步骤 |
| `Configuration-Reference.md` | 集中列出目录、命令参数、输入字段与输出文件 |
| `Troubleshooting.md` | 按现象提供诊断步骤、原因和修复方式 |
| `_Sidebar.md` | 提供稳定的 GitHub Wiki 全局导航 |

## 内容组织

1. 首页先给出三条常见路径：只查看日历、作为 Skill 使用、自动更新。
2. 每个操作页按“目标、前置条件、步骤、验证、下一步”组织。
3. 命令默认从仓库根目录执行，并明确 macOS 与 Linux 的差异。
4. 对危险或容易误解的行为使用提示块，尤其是公网上传占位、过期链接、示例数据和 30 天清理策略。
5. 页面之间使用 GitHub Wiki 页面名链接；指向仓库源码时使用相对仓库链接并注明发布到独立 Wiki 后可能需要调整。

## 事实来源

- `README.md` 和 `SKILL.md` 用于确认项目定位与用户工作流。
- `scripts/*.py` 用于确认参数、输入字段、输出目录和错误行为。
- `web/build.py` 与 `web/src/` 用于确认构建方式和数据契约。
- `prompts/` 与 `cron/` 用于确认豆包定时任务提示词和 cron 调度边界。

## 验收标准

- 首次使用者只阅读 Wiki 即可打开 `web/index.html` 并生成一份测试 Excel。
- 页面明确说明 `publish_calendar_data.py` 不会自行上传文件，必须提供真实的 `--url` 或使用平台上传能力。
- 页面不把不存在的 `scripts/run_tick.sh` 描述为仓库内可直接运行的脚本。
- 所有本地文件链接和 Wiki 页面链接均可解析。
- 所有示例命令与当前脚本的命令行接口一致。
- Wiki 能回答安装、运行、更新、自动化和常见故障五类用户问题。

## 验证方式

- 执行 Python 语法检查与 `web/build.py` 构建验证。
- 使用临时目录运行 Excel 追加脚本，避免污染仓库数据。
- 扫描 Markdown 内部链接和页面导航。
- 用无前置上下文的读者测试检查 Wiki 是否能独立回答典型问题。
